# MAGI Runtime v0.2-P-r1 开发计划

## 路线定位

v0.2-P-r1 从 `v0.1-baseline` 分支开始，不依赖 `v0.2-r1` 的未完成实现。Paseo 负责 Agent Runtime mechanics，MAGI 保留 Governance Authority，ControlledExecutor 负责独立验证。

```text
Paseo runs agents.
MAGI governs agents.
ControlledExecutor verifies independently.
Human remains final authority.
```

## 本版本硬性约束

- P0-1 Paseo SDK Spike 完成前，不冻结 `AgentRuntimeBackend` 接口；
- Spike 必须同时探测 cancel、并发、session、provider、事件、reconnect 和 orchestration 关闭能力；
- 第一条垂直切片采用 Codex-only，先验证 HYP-2，再做三贤人横向扩展；
- GATE-2 必须有 ACP/MCP/native/CLI/daemon/workspace 路径排查报告，不能只靠单测；
- OpinionNormalizer 必须基于真实 Codex tool-call/prose 样本设计，禁止预设 strict JSON 永远可靠；
- Agent completion 不等于 MAGI Task completion；Agent observation 不等于 policy-grade Evidence；
- P0 ControlledExecutor 只提供 minimum process containment，不宣称完整 sandbox；
- 明确记录验证会执行不可信测试代码、Paseo daemon compromise 不可抵抗等残余风险；
- 真实 Agent 接入前不得改变 v0.1 的 State、Risk、VETO、Evidence Trust 和 HumanGate 语义。

## 当前基线

- 分支：`v0.2-p`；
- 基线：`v0.1-baseline`；
- v0.1：49 个测试通过；
- v0.2-P-r1 当前不直接复用未验证的 Provider-specific wrapper；
- 当前工作区已有的 v0.2-r1 手册和审查文档不作为本计划的自动提交内容。

## P0 开发顺序

### P0-0：Freeze v0.1

- 运行 v0.1 全部测试和 Demo；
- 固化 Trust Model、StateMachine、Policy、Evidence、HumanGate 现状；
- 确认 baseline tag/commit 可重放。

验收：v0.1 全部测试通过，Governance semantics 无变化。

### P0-1：Paseo SDK Spike

只写 Spike，不写 production Backend。真实探测：

- connect、provider selection、create agent；
- cwd、send、receive result；
- event subscription、wait、status、cancel；
- 多 Agent 并发、session continuity、reconnect（如支持）；
- timeout、error、provider failure；
- Paseo MCP injection、ACP、provider-native tool、CLI、daemon endpoint、workspace/schedule/subagent 能力。

产出：`docs/reviews/paseo-sdk-capability-report.md`，逐项记录 SDK primitive、实际语义和限制。

### P0-2：Backend 依据 Spike 定稿

Spike 报告完成后，才决定是否保留通用：

```ts
FakeAgentBackend
PaseoAgentBackend
```

接口必须基于真实 Paseo primitive，不预设七方法模型。Backend 只能传输和记录 Runtime mechanics，不能拥有 Governance authority。

### P0-3：GATE-2 Paseo Orchestration Isolation

建立专用 Paseo daemon/config/session/workspace root，排查并记录：

- Paseo MCP 注入；
- ACP tool 暴露；
- provider-native subagent；
- 继承的 MCP 配置；
- Paseo CLI/binary；
- local daemon endpoint；
- workspace creation、schedule、heartbeat、subagent API。

产出：`docs/reviews/paseo-orchestration-isolation-report.md`。

若只能依靠 Prompt 阻止 unmanaged Agent 创建，P0 = NO-GO。

### P0-4：Codex-only Normalizer Spike

先选 Codex，采集真实 Paseo 输出 fixture：

- strict/非 strict tool-call；
- prose + JSON；
- markdown-wrapped JSON；
- partial/malformed JSON；
- claims、risk、VETO、artifact refs；
- tool-call 与自然语言混合；
- 超长输出。

形成：

```text
RawAgentResult
→ OpinionNormalizer
→ AgentSubmission
→ Schema Validation
```

Normalizer 只能提取、映射、规范化和一次格式修复，不能创造 Claim/VETO/Risk/Evidence authority。

### P0-5：Normalizer Stability Gate

在真实 Codex 样本稳定后扩展 OpenCode/Hermes。建议初始门槛：

```text
first-pass valid >= 90%
valid after <=1 repair >= 98%
```

三 provider 各自保存 fixture、metrics 和失败样本。未达标时 P0 NO-GO。

### P0-6：Workspace 与 Paseo Trust Boundary

实现/验证：

- `WorkspaceLease`；
- MELCHIOR READ_ONLY；
- BALTHASAR isolated READ_WRITE；
- CASPER NONE；
- Context/Session/Workspace/Capability isolation；
- Paseo 定位为 trusted-for-runtime-mechanics、untrusted-for-governance。

明确记录：Git worktree isolation 不等于 OS security sandbox；Paseo daemon 被完全攻破不在 P0 防护承诺内。

### P0-7：ControlledExecutionRuntime

实现最小 containment：

- dedicated process；
- isolated cwd；
- sanitized env；
- no MAGI credentials；
- timeout/cancel；
- bounded stdout/stderr；
- parent/child/grandchild/watch process cleanup；
- explicit executable + argv；
- 禁止 raw agent shell string。

残余风险必须显式写入文档：这不是完整 sandbox，验证仍会执行不可信测试代码。

### P0-8：PatchSnapshot 与 TOCTOU

实现不可变 PatchSnapshot，覆盖：

- modified/new/deleted/renamed files；
- untracked files；
- executable bit；
- symlink；
- canonical path；
- base revision、diff/tree hash。

验证流程：

```text
Implementation Workspace
→ PatchSnapshot
→ hash/freeze
→ Fresh Verification Input
→ recompute
→ mismatch = PATCH_CHANGED
```

### P0-9：Real Three Sages Evaluation

只有 P0-1、GATE-2、P0-5、P0-7、P0-8 通过后，才开启三贤人并发评估。第一阶段仍保留 Codex-only 垂直切片作为主验收路径。

### P0-10：Codex Implementation

只有 MAGI Policy APPROVE 后才允许 Codex Implementation，输出 immutable PatchSnapshot。禁止修改 base repo、push main、merge、deploy 或改变 VerificationPlan。

### P0-11：Independent Verification

```text
PatchSnapshot
→ Fresh Verification Input
→ ControlledExecutor
→ Runtime-owned Artifact
→ EvidenceVerifier
→ Policy-grade Evidence
```

Agent-observed PASS/FAIL 和 Agent self-produced Artifact 默认不能成为 Hard Gate。

### P0-12：CLI / Doctor / Explain / Approval UX

至少提供：

```bash
magi run
magi status <task-id>
magi explain <task-id>
magi approve <approval-id>
magi reject <approval-id>
magi cancel <task-id>
magi doctor
```

`magi doctor` 必须能分别显示 MAGI、Paseo、Provider、Normalizer、Workspace、ControlledExecutor、Orchestration Isolation 状态。

### P0-13：GO / NO-GO Review

GO 必须同时满足：

- Paseo SDK semantics 足够稳定；
- Backend 不改变 Governance semantics；
- 三 Normalizer 达标；
- GATE-2 orchestration escape 技术排查通过；
- ControlledExecutor minimum containment 通过；
- PatchSnapshot/TOCTOU 通过；
- Codex-only 端到端闭环通过；
- HYP-2 三贤人相较 Codex-only 有可观测价值。

以下任一成立即 NO-GO：

- Agent-side orchestration 无法技术限制；
- Normalizer 长期不稳定；
- 为接 Paseo 必须放宽 Trust Model；
- Process tree 无法清理；
- PatchSnapshot 无法可靠表达实现状态；
- Controlled Verification 无法与 Implementation 独立；
- 三贤人价值相较 Codex-only 不明显。

## P0 测试与证据

至少准备：

```text
01-simple-bug
02-runtime-failure
03-architecture-conflict
04-history-risk
05-hallucinated-evidence
06-prompt-injection
07-orchestration-escape
08-process-tree
09-patch-toctou
```

关键验收：

- Codex claim FAIL、ControlledExecutor PASS：不触发 Hard VETO；
- Codex claim PASS、ControlledExecutor FAIL：Controlled Evidence 优先；
- Agent self-proof：`SELF_PRODUCED`, `policyGrade=false`；
- Prompt Injection 不得改变 Governance；
- Agent 无法通过 Paseo 创建 unmanaged Agent；
- timeout/cancel 后无 orphan process；
- Patch 改变后旧 verification/approval 失效；
- Audit 保持现有 redaction。

## 明确残余风险

交付文档必须声明：

1. P0 ControlledExecutor 不是完整 sandbox；
2. Verification 仍会执行不可信 Repository 的测试/构建代码；
3. Paseo daemon 若被完全攻破，P0 不承诺抵抗；
4. Git worktree、dedicated daemon 和 observer-only 是风险缓解，不等于 OS/Kernel 级隔离；
5. P0 不宣称完美 Prompt Injection Detection、完整 Supply-chain Attestation、多租户隔离或生产级 RBAC。
