# MAGI Runtime v0.2-r1 开发计划

## 版本目标

v0.2-r1 将 v0.1 的确定性 Runtime 从 FakeAgent/MVP 边界推进到真实 Agent、持久化 Runtime、独立验证和安全边界。核心目标是：真实 Agent 接触真实 Repository、模型 API、工具、文件和执行环境后，仍不能越过 Runtime 的 State、Policy、Evidence、Human Gate 和安全边界。

## 当前基线

v0.1 已完成：

- 确定性 StateMachine 和 PolicyEngine；
- FakeAgent、Schema 校验、有限 Retry/Repair；
- Artifact provenance、EvidenceVerifier、verified VETO；
- HumanGate、Audit、Decision Snapshot；
- Fake Execution、Validation、Runtime CLI 和交互式验收；
- 49 个测试通过。

v0.1 的已知边界：

- Store 实际为 InMemory；
- 没有真实 Agent Adapter；
- 没有 Workspace/Sandbox/Capability/Secret Boundary；
- Fake Execution 尚不是 ControlledExecutor；
- Evidence 尚未完整表达 independence/policyGrade；
- Audit 尚无 hash chain；
- CLI 尚未实现跨进程持久化恢复。

## 安全硬约束

- Fake/Real Agent 都视为不可信、tainted 输入源；
- Agent 不能决定 State、Policy、Human Approval、Evidence Trust、Risk Downgrade、Retry、Repair Limit 或 Execution Authorization；
- Agent Claim、Agent-observed test 和 Agent 自产 Artifact 默认不是 policy-grade Evidence；
- 不执行未经 Schema、Canonicalization、Allowlist、Boundary Check 的 path、command、URL、artifact id 或 tool argument；
- Control Network 与 Workload Network 分离；Workload Network 默认 DENY；
- Adapter Control Credential 不得进入 Agent Context、Tool subprocess、Repository、Artifact 或 Audit；
- REQUIRED 安全边界无法建立时必须 FAILED 或 HUMAN_WAIT；
- v0.2-r1 不实现 Pi、Round 2、Debate、Weighted Voting、ConsensusEngine 或自动学习。

## 开发阶段与 Gate

### Phase 0：冻结 v0.1 Baseline

- 运行全部 v0.1 测试和 Demo；
- 创建 baseline tag/commit；
- 记录 State、Policy、Evidence、HumanGate 和安全边界现状；
- 确认 v0.2 改动不破坏 v0.1 行为。

Gate：v0.1 全部测试通过，基线可重放。

### Phase 1：Persistence Foundation

- 保留现有 Store Interface 和 InMemory 实现；
- 实现 SQLite Task/Audit/Artifact/Approval/AgentRun/Workspace/DecisionSnapshot Store；
- 增加 `stateVersion` 乐观锁；
- 实现 Cross-table Transaction；
- 实现 Runtime restart recovery；
- 保证 State 与 Audit 事务一致。

Gate：HUMAN_WAIT、EVALUATING、EXECUTING、VALIDATING 重启恢复；Approval/Task 更新不可出现半完成状态。

### Phase 2：Protocol / Trust Upgrade

- `RawAgentResult`；
- `AgentSubmission`；
- `EvaluatedOpinion`；
- `VerifiedEvidence`；
- `AgentEvent`；
- `AgentRunRecord`；
- `OpinionNormalizer` 与一次 Schema repair；
- Evidence 的 provenance、integrity、independence、policyGrade。

Gate：PolicyEngine 消费 EvaluatedOpinion，而不是未经验证的 AgentOpinion。

### Phase 3：Security Boundary

- WorkspaceManager；
- ContextBuilder；
- AgentSandbox；
- CapabilityPolicy；
- SecretGuard；
- Credential Boundary；
- Control/Workload Network model；
- Sensitive Path deny；
- Process Tree cleanup；
- Fail-closed Boundary Matrix。

Gate：所有 REQUIRED boundary 可验证建立；失败时不能降级为 warning 后继续。

### Phase 4：ControlledExecutor

- PatchSnapshot；
- Fresh Verification Workspace；
- Runtime-owned VerificationPlan；
- 结构化 CommandTemplate；
- ControlledExecutor；
- Runtime-owned Artifact；
- lockfile/manifest mutation 检测；
- timeout/cancel/process cleanup。

Gate：验证只能在 fresh workspace 进行；Agent 返回的 shell string 不能直接执行；Agent 自证不能成为 policy-grade Evidence。

### Phase 5：Real Agent Infrastructure

- Adapter lifecycle；
- Raw result persistence；
- AgentEvent 去重；
- late result 安全处理；
- timeout/cancel；
- session/workspace/capability 绑定；
- OpinionNormalizer 稳定映射。

### Phase 6–8：Real Agents

1. OpenCode / MELCHIOR：READ_ONLY、ArchitectureContext、禁止写 base repo；
2. Codex / BALTHASAR Evaluation：isolated worktree，结果为 AGENT_OBSERVED；
3. Hermes / CASPER：HistoryContext、无完整 Repository、只提供风险和历史分析。

### Phase 9：真实三贤人独立评估

验证不同 Session、Context、Workspace、Capability，且不得读取彼此 Submission。

### Phase 10–11：Implementation 与 Independent Verification

- Policy APPROVE 后才允许 Codex Implementation；
- 生成 immutable PatchSnapshot；
- 在 fresh workspace 通过 ControlledExecutor 验证；
- Controlled Evidence 优先于 Agent claim；
- Patch、VerificationPlan、Evidence Set 改变时旧 Approval 必须 STALE。

### Phase 12：Security Torture Test

执行手册 S01–S24，包括 Prompt Injection、Self-proof、Workspace Escape、Secret Read、Credential Leak、Network、Command Injection、Dependency Mutation、Late Result、Approval Race、Process Tree Escape 和 Audit Chain Modification。

### Phase 13–14：OpenClaw 与 Benchmark

- OpenClaw 只负责 Ingress、Identity、Session、Notification、Approval UI、Status UI；
- 不复制 MAGI Policy；
- 对比 Codex only、OpenCode only、Hermes only 和 MAGI 的正确性、成本、延迟、人工升级和 Repair 指标。

## 首要接口演进

```text
Artifact
  → provenance + independence + policyGrade

AgentOpinion
  → AgentSubmission + EvaluatedOpinion

EvidenceVerificationResult
  → VerifiedEvidence

ApprovalRequest
  → task/decision/patch/verification/evidence hashes

AuditEvent
  → previousHash + hash

TaskRecord
  → stateVersion
```

- OpenCode、Codex、Hermes 具备独立 Session/Context/Workspace/Capability；
- late result、duplicate event、Approval race、cancel cleanup 安全；

- v0.1 tests、S01–S24、F01–F08 和 persistence/restart tests 全部通过。
